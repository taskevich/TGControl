# TG Control

Веб-панель для работы с пулом Telegram-аккаунтов.

**Стек:** FastAPI · Telethon · PostgreSQL + SQLAlchemy 2 (async) + Alembic · Redis · React 18 + Vite · Recharts · Docker
Compose.

## Возможности

| Раздел                     | Что умеет                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
|----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Авторизация в панель**   | JWT-вход, выход с отзывом токена, защита от перебора (лимит попыток по IP), смена пароля, несколько пользователей панели                                                                                                                                                                                                                                                                                                                                                            |
| **Аккаунты**               | Кнопка "Добавить аккаунт": вход по номеру (код + 2FA), импорт `.session` (Telethon и Pyrogram) с парными `.json` (app_id/app_hash/2FA/прокси/устройство), `.zip`-архивов, строковых сессий. Сессии хранятся в PostgreSQL в зашифрованном виде (Fernet). Проверка одного/всех, статусы (активен / не авторизован / забанен / ошибка), прокси на аккаунт, включение/отключение                                                                                                        |
| **Прокси**                 | Раздел "Прокси": список прокси (SOCKS5/SOCKS4/HTTP), добавление по одному и списком, проверка соединения с Telegram (статус и задержка), включение/отключение. Прокси **необязательно** привязывается к аккаунту (в настройках аккаунта, при добавлении аккаунта или автоматически - "Привязать к аккаунтам"). Клиент Telegram аккаунта запускается через привязанный прокси, а если прокси не привязан - напрямую                                                                  |
| **Чаты аккаунта**          | Выбор аккаунта -> список диалогов (кэш в Redis) -> сообщения с просмотрами/реакциями/ответами -> отправка, ответ на сообщение, просмотр ответов, выход из чата, вступление по ссылке                                                                                                                                                                                                                                                                                                |
| **Сохранение сообщений**   | Таблицы `message` и `tg_user`. В чате аккаунта старые сообщения подгружаются автоматически при прокрутке вверх, а новые запрашиваются у Telegram (RPC `messages.getHistory` с `min_id`) каждые 5 секунд. Всё загруженное сохраняется в БД вместе с авторами. Кнопка "Получить новые" и автообновление запрашивают новые сообщения во всех последних диалогах аккаунта (или всех аккаунтов)                                                                                          |
| **Все сообщения**          | Лента сохранённых сообщений всех аккаунтов (раздел "Все сообщения") или одного аккаунта (вкладка "Сообщения"), с бесконечной прокруткой и фильтрами по аккаунту, чату, автору, типу чата, входящим/нашим и тексту                                                                                                                                                                                                                                                                   |
| **Прочитать все**          | Кнопка "Прочитать все" во вкладке "Чаты" аккаунта и на странице "Аккаунты" (для всех активных аккаунтов). Отмечаются прочитанными все диалоги, включая архив, каждую тему форумов, упоминания, реакции и чаты, помеченные "непрочитанным" вручную. FloodWait до `FLOOD_WAIT_MAX` выжидается                                                                                                                                                                                         |
| **Файлы в S3**             | Медиа и файлы сохранённых сообщений (фото, видео, голосовые, кружки, стикеры, GIF, аудио, документы) в фоне скачиваются из Telegram и выгружаются в S3-хранилище. Файлы больше `MEDIA_MAX_SIZE_MB` (по умолчанию 1 ГБ) не скачиваются. Раздел "Все файлы" и вкладка "Файлы" аккаунта: статистика (по статусам, типам, чатам, аккаунтам), галерея с предпросмотром фото, видео и аудио, просмотр и скачивание. В ленте сообщений фото, видео и аудио показываются прямо в сообщении. |
| **Рассылка**               | От выбранных или всех активных аккаунтов: сообщения в чаты/пользователям или комментарии к постам каналов. Перед отправкой проверяются права (участник ли аккаунт, запрет на отправку, ограничения, права публикации в канале); аккаунты без прав **пропускаются**. Паузы между действиями, обработка FloodWait, опция "вступить, если нужно"                                                                                                                                       |
| **Вступление / выход**     | Для всех или выбранных аккаунтов, по `@username`, `t.me/chat`, инвайтам `t.me/+hash`, ID. Для одного аккаунта - вкладка "Действия"                                                                                                                                                                                                                                                                                                                                                  |
| **Задачи**                 | Массовые действия выполняются в фоне, с прогрессом, отменой и детальным журналом по каждому аккаунту и цели                                                                                                                                                                                                                                                                                                                                                                         |
| **Статистика**             | Все сообщения/комментарии, отправленные из панели, отслеживаются: просмотры, реакции (по эмодзи), репосты, количество комментариев к написанному комментарию, история изменений (графики). Автообновление по расписанию. Можно добавить любое сообщение по ссылке, например комментарий, написанный вручную (`t.me/channel/123?comment=456`)                                                                                                                                        |
| **Комментарии к аккаунту** | Ответы на сообщения/комментарии аккаунта и упоминания аккаунта в группах - на странице аккаунта и в общем разделе "Комментарии"                                                                                                                                                                                                                                                                                                                                                     |

## Быстрый старт (Docker)

1. Получить `api_id` и `api_hash` на <https://my.telegram.org> -> API development tools.
2. Скопируйте настройки и заполните их:
   ```bash
   cp .env.example .env
   # укажите SECRET_KEY, ADMIN_PASSWORD, TG_API_ID, TG_API_HASH
   ```
3. Запустите:
   ```bash
   docker compose up -d --build
   ```
4. Откройте <http://localhost:8080> и войдите под `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Сразу смените пароль в
   "Настройках".

Миграции Alembic применяются автоматически при старте бэкенда.

## Хранилище файлов (S3)

В Docker ничего настраивать не нужно: сервис `s3` (SeaweedFS) поднимается вместе с панелью, бакет `S3_BUCKET` создаётся
при старте бэкенда. Наружу хранилище не публикуется - файлы отдаются через панель (`/api/files/...`, подписанные ссылки
со
сроком действия, поддержка Range для перемотки видео), поэтому они открываются с любого компьютера, где открыта панель.

Внешнее хранилище - задайте в `.env`:

```env
S3_BUCKET=my-bucket
S3_ENDPOINT_URL=XXX
S3_REGION=XXX
S3_ACCESS_KEY=XXX
S3_SECRET_KEY=XXX
```

Файлы попадают в очередь при сохранении сообщения (прокрутка чата, "Получить новые", автосинхронизация); сообщения,
сохранённые до настройки хранилища, ставятся в очередь при старте. Объекты хранятся по ключу
`<аккаунт>/<чат>/<сообщение>/<имя файла>`. Без Docker при пустом `S3_BUCKET` файлы не сохраняются.

## Локальная разработка (без Docker)

Нужны Python 3.11+, Node 18+, PostgreSQL и Redis.

```bash
# база
createuser -P tgcontrol         # пароль tgcontrol
createdb -O tgcontrol tgcontrol

# бэкенд
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000

# фронтенд (в другом терминале)
cd frontend
npm install
npm run dev                     # http://localhost:5173, /api проксируется на :8000
```

`.env` читается из корня проекта (или из `backend/`).

Полезные команды:

```bash
python -m app.cli create-user manager secret123    # новый пользователь панели
python -m app.cli set-password admin newpass       # сброс пароля
python -m app.cli gen-key                          # ключ для SESSION_ENCRYPTION_KEY
alembic revision --autogenerate -m "..."           # новая миграция после изменения моделей
```

## Форматы импорта аккаунтов

- **`.session`** - SQLite-сессии Telethon или Pyrogram.
- **`.json`** рядом с `.session` с тем же именем (`79991234567.session` + `79991234567.json`) - поддерживаются
  распространённые ключи: `app_id`/`api_id`, `app_hash`/`api_hash`, `phone`, `twoFA`/`password`, `device`, `sdk`,
  `app_version`, `lang_pack`, `system_lang_pack`, `proxy` (строка или массив `[type, host, port, rdns, user, pass]`).
  Также `.json` со строковой сессией в поле `session_string`.
- **`.zip`** с любым набором файлов выше (вложенные папки допускаются).
- **Строковые сессии** Telethon или Pyrogram - по одной на строку (или `.txt`-файлом).

Каждая сессия проверяется подключением к Telegram, после чего аккаунт создаётся или обновляется (дубликаты определяются
по Telegram ID). `tdata` (Telegram Desktop) напрямую не поддерживается - сконвертируйте в `.session` (например, через
`opentele`).

Прокси: `socks5://user:pass@host:port`, `socks4://...`, `http://...` или `host:port:user:pass` (SOCKS5). Прокси из `.json`
имеет приоритет над выбранным в форме импорта.

## Прокси

- Таблица `proxies` (схема, хост, порт, логин, пароль - зашифрован), связь `accounts.proxy_id` (может быть пустой).
- Нет привязки -> клиент аккаунта подключается к Telegram напрямую. Есть привязка -> только через этот прокси.
- Если привязанный прокси **отключён**, аккаунт не подключается (без "тихого" перехода на прямое соединение) - включите
  прокси или отвяжите его.
- При удалении прокси привязанные аккаунты переходят в режим "без прокси" (панель предупреждает об этом).
- Проверка прокси - TCP-соединение через прокси до сервера Telegram (149.154.167.51:443).
- Миграция `0003_proxies` переносит прокси, ранее указанные строкой в аккаунтах, в новую таблицу и привязывает их.
- API: `GET/POST /api/proxies`, `POST /api/proxies/bulk`, `PATCH/DELETE /api/proxies/{id}`,
  `POST /api/proxies/{id}/check`, `POST /api/proxies/check-all`, `POST /api/proxies/assign`; у аккаунта -
  `PATCH /api/accounts/{id}` с `proxy_id` (`null` - без прокси) или `proxy` (URL нового прокси).

## Сохранение сообщений

- `tg_user` - пользователи Telegram, встреченные как авторы сообщений (id, username, имя, телефон, бот/premium).
  Обновляются при каждом новом сообщении автора.
- `message` - сообщения чатов: аккаунт, чат (id, название, username, тип), id сообщения, автор (`sender_id` для любого
  отправителя, `tg_user_id` для пользователей), текст, медиа, ответ на, просмотры, реакции, количество ответов, даты
  отправки и изменения. Уникальность - (аккаунт, чат, id сообщения); повторная загрузка обновляет текст, реакции и
  просмотры.
- Сообщения попадают в БД: при прокрутке чата в панели, при опросе новых в открытом чате, по кнопке "Получить новые" и в
  фоне, если задан `MESSAGES_SYNC_MINUTES`. При синхронизации запрашиваются только диалоги, где последнее сообщение
  новее сохранённого, поэтому лишних запросов к Telegram нет.
- Статистика по ним - вкладка "Сообщения чатов" в разделе "Статистика": входящие/исходящие, чаты, авторы, активность по
  дням, топ чатов и авторов, просмотры/реакции/ответы на сообщения наших аккаунтов, лучшие исходящие сообщения; фильтр
  по аккаунту и периоду (`GET /api/stats/chat-messages`).
- API: `GET /api/messages` (курсор `before_date` + `before_id`, фильтры), `GET /api/messages/chats`,
  `GET /api/messages/summary`, `POST /api/messages/sync`,
  `GET /api/accounts/{id}/dialogs/{peer}/messages/new?after_id=`, `GET /api/tg-users`, `GET /api/tg-users/{id}`.

## Как считается статистика

- **Просмотры** Telegram отдаёт только для сообщений в каналах; в группах и комментариях их нет - в панели будет "-".
- **Реакции** - по каждому эмодзи и суммарно.
- **Комментарии к написанному комментарию** - ответы на наше сообщение: в ветке поста (для комментариев к каналам) или в
  истории чата. Найденные ответы сохраняются в таблицу `comments` и видны на странице сообщения и аккаунта.
- **Упоминания** - кнопка "Собрать комментарии" на странице аккаунта сканирует группы аккаунта (фильтр "мои упоминания";
  в него попадают и ответы на сообщения аккаунта).
- Автообновление: каждые `STATS_REFRESH_MINUTES` минут для сообщений за последние `STATS_REFRESH_DAYS` дней (0 -
  выключить). Каждое обновление сохраняет снимок для графика динамики.

## Структура

Backend и frontend разложены по слоям Clean Architecture. Зависимости направлены только внутрь:
`presentation -> application -> domain`; `infrastructure` реализует порты `application` и тоже зависит только от
внутренних слоёв. Все слои связывает композиционный корень.

```
backend/app/
  domain/              сущности и правила без фреймворков: entities.py (Account, Proxy, BulkTask, ...),
                       values.py (разбор ссылок/целей Telegram, адрес прокси, телефон), errors.py (бизнес-ошибки)
  application/         сценарии использования
    ports/             интерфейсы: репозитории + Unit of Work, Telegram (сессия, пул, вход), шифрование,
                       токены, key-value хранилище, проверка прокси, разбор файлов сессий
    services/          общие сервисы: доступ к Telegram от имени аккаунта, архив сообщений, трекинг статистики
    use_cases/         auth, accounts, account_onboarding (вход по номеру, импорт), proxies, chats,
                       bulk (массовые задачи), stats, messages
    dto.py, policies.py
  infrastructure/      адаптеры: db/ (таблицы, императивный маппинг сущностей, репозитории, UoW), telegram/
                       (Telethon: клиенты, пул, конвертеры, разбор .session), redis_store.py, security.py
                       (bcrypt, JWT, Fernet), proxy_checker.py, config.py (настройки из .env)
  presentation/        http/ (FastAPI: роутеры, схемы, презентеры, ошибки домена -> HTTP-коды), cli.py
  container.py         композиционный корень: собирает адаптеры и сценарии
  main.py              точка входа uvicorn
  alembic/             миграции
frontend/src/
  domain/              правила без React: подписи аккаунтов, статусы, прокси, форматирование
  application/         контекст сервисов (useServices), авторизация, хуки (useQuery, useInterval)
  infrastructure/      HTTP-клиент, токен сессии, шлюзы к API по ресурсам
  presentation/        App, страницы и компоненты - работают только через useServices()
  main.jsx             композиционный корень
docker-compose.yml
```

## Важно

- Бэкенд должен работать **в одном процессе** (`--workers 1`): клиенты Telethon и фоновые задачи живут в памяти
  процесса.
- Не меняйте `SECRET_KEY`/`SESSION_ENCRYPTION_KEY` после добавления аккаунтов - сессии перестанут расшифровываться.
- Массовые рассылки и вступления - частая причина ограничений и банов аккаунтов. Используйте прокси, разумные паузы и
  соблюдайте правила Telegram.
